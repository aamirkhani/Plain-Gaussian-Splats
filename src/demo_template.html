Pull the Gaussians slider down and the bulldozer dissolves into the blobs it is actually made of. They are ordered by how much of the image each one carries, so the first few hundred sketch the silhouette and the last forty thousand are detail. That is what adaptive density control produced: it started from 50,000 random points in a cube.

To see individual splats: hit Zoom in a few times, then switch Shape from gaussian to discs or outlines. Gaussian is the honest render — alpha falls off as exp(−½ dᵀΣ′⁻¹d), so neighbours blend and you cannot tell where one ends. Discs cut every splat off hard at 2σ and outlines draw only the rim, which turns the soft cloud into the thousands of overlapping ellipses it really is. Each ellipse is one 3D gaussian squashed through the projection Jacobian.

02

What the hardware actually allowed

The constraint was an integrated GPU with no private video memory and a 12 GB budget shared with the CPU. Memory was never the problem — bandwidth was.

Roughly 500× on the bandwidth-bound side, using about 0.1% of the arithmetic budget. Matrix cores would have bought nothing.

03

Four optimisations, one survivor

Each variant was checked against the eager fp32 reference on both the image and the gradients. That second column is the one that decided it.

VariantSpeedImage err Gradient errVerdict
eager fp321.00×——baseline
bf16, fp32 scan1.23×4.1e−024.1e−01rejected
bf16, full1.40×5.0e−024.1e−01rejected
power-of-two padding0.64×2.4e−071.8e−06slower
Triton fusion, pointwise prefix1.86×3.6e−075.5e−04adopted

bf16 rendered a perfectly plausible image while carrying 41% gradient error. Checking only the forward pass would have shipped a “speedup” that quietly degrades training. The cause was catastrophic cancellation: dx = pixel − mean subtracts two numbers near 400 to get a value near 1, and bf16’s 8 mantissa bits are worth ±1.6 px at that magnitude — larger than the answer.

04

Where the model stops being true

Every training camera sat in the upper hemisphere, between 7° and 89° elevation. Below that band nothing ever constrained the geometry, so the underside of the baseplate is reconstruction garbage — not a renderer bug. The viewer above clamps elevation to the supervised range, which is why you cannot tip it under the model. A splat is only valid where a camera looked.
